지금은 계정마다 브라우저를 따로 띄웁니다. 어느 창이 어떤 계정인지 일일이 확인하고, 손으로 로그인하고, 스크립트도 제각각 돌리죠. 그러다 실수로 다른 계정에 글을 올리기도 합니다.

Ply는 이 작업을 한곳에 모았습니다. 탭 하나가 곧 계정 하나라 에이전트가 탭 안에서 바로 움직입니다. 로그인된 화면을 직접 다루고, 무거운 작업은 기존 서버에 그대로 넘깁니다.

하는 일

로그인, 작성, 발행, 삭제, 예약까지.
매일 반복하던 일들입니다.

말 한마디로 지시

“myblog01로 강아지유치원 글 2개 써줘”라고 입력하면 로그인부터 예약 발행까지 이어서 마칩니다.

조건이 많을 땐 폼으로

날짜, 건수, 간격, 스타일처럼 챙길 조건이 많으면 대화 대신 깔끔한 입력창을 띄워 줍니다.

기존 서버 그대로 활용

원고 생성과 예약 발행은 기존에 쓰던 서버 인프라에 그대로 맡기면 됩니다. 새로 옮길 필요가 없습니다.

계정

탭 하나에 계정 하나.
서로 꼬이지 않습니다.

독립된 브라우저 세션

계정마다 쿠키 저장소가 완전히 나뉩니다. 한 창에 5개를 띄워도 데이터가 섞이지 않습니다.

작업 탭은 따로 분리

에이전트가 띄운 탭은 사이드바에 따로 모입니다. 내가 보고 있던 화면을 가리지 않습니다.

비밀번호는 로컬 기기에만 보관

기기 키체인에 암호화해 두고 로그인할 때만 꺼내 씁니다. AI 모델 쪽으로는 아예 넘어가지 않습니다.

안전

삭제 전에는 꼭 확인합니다.
네이버엔 되돌리기 기능이 없으니까요.

삭제 대상 목록 확인

제목과 작성일을 먼저 보여주고 승인할 때만 지웁니다. 승인하지 않으면 즉시 취소됩니다.

언제든 즉시 중단

정지 버튼을 누르면 다음 작업으로 넘어가지 않습니다. 지금 작업 중인 글 1건만 끝내고 멈춥니다.

엉뚱한 글 번호 삭제 방지

화면 목록에서 실제로 불러온 글만 삭제할 수 있습니다. 목록에 없는 번호는 알아서 걸러냅니다.
